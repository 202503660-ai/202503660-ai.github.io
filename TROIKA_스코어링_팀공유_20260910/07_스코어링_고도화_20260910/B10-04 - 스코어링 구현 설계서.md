# 스코어링 구현 설계서

> 아래 수식·가중치·시간 임계값은 이번에 제안하는 설계다. 현장 확인·팀 합의·재산출을 완료한 모형이 아니다. 기존 `score_v3.py`와 혼동하지 않도록 다음 구현 버전은 `score_v4`로 구분한다.

## 1. 의사결정 단위와 처리 흐름

```
상권 16곳의 동일 정의 입력
  → N·A·V 진단 + 결측/출처 표시
  → 개별 점포의 범위·동의·안전·운영 확인
  → 예산/권역/동선 제약을 만족하는 점포 묶음 선정
  → 당일 운영자가 승인한 범위에서 추천
  → 사후 방문·쿠폰 사용·추가 소비 평가
```

- 상권 i: 통계와 정책 진단 단위. TRDAR_CD로 식별한다.
- 점포 j: 실제 제휴 결정 단위. 공식 점포 ID 또는 자체 안정 ID를 사용한다.
- 경로 e: 안전과 이동시간 확인 단위. 상권 중심점과 점포 입구를 혼동하지 않는다.
- 시간 t: 당일 추천·수용력 확인 단위. 일괄 정적 점수와 별도 버전을 갖는다.
- 범위는 B9 참여존을 승계한다. 16개 상권 포함만으로 그 상권의 모든 점포가 실제 경계 안에 있다는 뜻은 아니다. 경계 걸침은 점포 좌표와 B9 규칙으로 판정한다.
- 발표용 최소모형과 실제 운영모형을 분리한다. 현장 정보가 없어도 진단은 가능하지만 최종 제휴·안전 승인은 불가능하다.

## 2. 입력 계약

모든 원자료에 `source_url / downloaded_at / period / boundary_version / unit / observed_or_proxy`를 붙인다. 명칭 대신 코드로 결합한다.

| 입력 | 한 행의 의미·핵심 필드 | 검증 규칙 |
|---|---|---|
| area_master | 상권 1곳: area_id, name, zone, tier, area_m2 | 16개 ID 유일. 면적 양수. B9 버전 고정 |
| area_quarter | 상권×분기×업종: sales_est_krw, stores, closures, footfall | 동일 업종 집합. 총계와 하위 업종 중복 합산 금지 |
| access_matrix | 출발점×점포/대표점: origin_id, target_id, minutes, method | 세 대학 출입구·무대와 역 출구 분리. 통행 불가는 INF |
| shop_registry | 점포 1곳: shop_id, area_id, entrance_coord, category | 중복 지점 검토. 좌표 기준 상권 연결. 제휴 대상 업종 표기 |
| shop_operations | 점포×운영시간: consent, open, slot_capacity, gate_status | 서명/확인일·확인자·제한 조건 보존 |
| route_review | 경로: emergency_access, queue_space, accessibility, closure | 통과/보류/제외, 근거와 대체 경로 |
| exposure_log | 익명 추천 세션: displayed, selected, visited, redeemed | 원시 개인 위치 추적 없이 필요한 집계만. 보존기간 팀 확정 |

기준 기간은 우선 **2025년 수준 / 2024→2025 변화**로 동결한다. 파일별 기준이 다르면 먼저 재집계한다. 2021~2025 장기 지수는 동일 경계·정의의 자료임을 입증한 뒤 보조로 사용한다. 공식 공지는 표준단위구역 기준 매출을 2021년부터 제공한다고 안내하므로 “2024 이전 자료는 전부 비교 불가”로 단정하지 않는다. [추정매출 메타데이터](https://data.seoul.go.kr/dataList/OA-15572/A/1/datasetView.do)

### 결측·정규화 규칙

1. 관측 0, 결측 NA, 적용 대상 아님을 구분한다. 매출건수로 유동인구를 대체하지 않는다.
2. 새 산출의 비교 집단은 고정된 16곳이다. 권역별로 다시 정규화하지 않는다.
3. 양의 방향 순위 점수: `p(x)=(평균순위(x)-1)/(n-1)`. 역방향은 `1-p(x)`.
4. 유효 n<2는 NA. 전 값이 같으면 0.5로 처리한다. 같은 값은 평균순위를 사용한다.
5. 원자료와 순위 점수를 나란히 제공한다. 순위화는 실제 격차를 보존하지 않는다.
6. 공통모형에 필요한 항목이 없으면 해당 결과는 NA. 값이 있는 후보끼리만 계산한 결과는 ‘부분집단 참고’로 분리한다.
7. 모형을 단순화할 때는 전 후보에 같은 축소모형을 적용한다. 상권마다 서로 다른 가중치로 재정규화하지 않는다.
8. 작은 표본의 세밀한 순위 차이는 과해석하지 않는다. 원점수 비교에는 반올림 전 값을 사용한다.

정규화·결측·가중치·변수 선택 모두 민감도 대상이다. [OECD/JRC 복합지표 핸드북](https://www.oecd.org/content/dam/oecd/en/publications/reports/2008/08/handbook-on-constructing-composite-indicators-methodology-and-user-guide_g1gh9301/9789264043466-en.pdf)

## 3. 지표 정의

### N — 정책적 지원 필요성

최소모형은 두 항만 사용한다.

```
g_i = (2025년 추정매출 합계 / 2024년 추정매출 합계) - 1
c_i = Σ(2025년 분기 폐업점포수) / Σ(2025년 분기 점포수)

N_i = 0.60 × p(-g_i) + 0.40 × p(c_i)
```

- c는 **점포수로 가중된 분기 폐업강도**다. 연간 폐업확률이 아니며, 기존 코드의 기간 필터 없는 `close12`를 재사용하지 않는다.
- g의 2024년 분모가 0·결측이면 NA. 업종별 자료의 합계 범위·포함률을 확인한다.
- 높은 N은 이 후보 집단 안의 상대적 지원 우선도다. 전체 상권이 성장해도 상대적 하위는 생기므로 실제 매출 감소 여부를 별도 열로 표시한다.
- 업종 구성이 다른 효과를 확인하기 위해 업종군별 증감과 점포당 추정매출 변화도 보조로 비교한다. 이 값을 N에 자동 중복 가산하지 않는다.
- 기존 ‘매출÷유동’은 **유동 대비 추정매출 강도**로 이름을 바꾸고 참고 진단으로만 둔다. 구매자/방문자의 비율이 아니므로 소비 전환율이 아니다.
- 매출·유동의 서로 다른 표준화 지수 차이는 ‘괴리’일 뿐, 돈을 안 쓰고 지나갔다는 관측이나 체류 실패의 증명이 아니다.
- 축제 이력은 ‘있음/없음 확인/미확인’으로 기록한다. 검색에서 안 나왔다고 미수혜 가점을 주지 않는다.
- HH·HL·LH·LL은 범주형 참고 정보다. 정렬하거나 N에 일괄 가점하지 않는다.

### A — 실제 보행 접근성

실제 무대·출입구와 점포 입구까지의 보행시간을 사용한다.

```
t_stage,j = min(확정된 세 대학 행사 접근점에서 점포 j까지 허용 경로 시간)
t_station,j = min(운영 시간에 이용 가능한 역 출구에서 점포 j까지 허용 경로 시간)
a_j = 0.60 × 2^(-t_stage,j / h) + 0.40 × 2^(-t_station,j / h)
A_i = 해당 상권의 검증된 공통 후보 집합에 대한 a_j의 중앙값
```

- 반감시간 h=10분은 **시연 가정**. 5/10/15분을 비교하고 현장 보행으로 보정한다.
- 점포 입구가 없을 때는 상권별 사전에 고정한 대표 접근점으로 진단하며 `access_method=representative_proxy`를 표시한다. 표본 점포가 선택된 뒤 유리한 점만으로 A를 재계산하지 않는다.
- 실제 행사가 경희대 한 곳에서만 열리기로 확정됐다면 그 시나리오를 별도로 명시한다. 세 대학 행사 시나리오에 단일 경희대 기준을 섞지 않는다.
- 철도·간선 횡단은 실제 허용 경로·횡단 대기시간에 포함한다. 같은 장벽을 거리와 별도 점수에 중복 반영하지 않는다.
- 역을 출발점으로 쓴다는 이유로 모든 철도 횡단 페널티를 면제하지 않는다. 출구·연결 통로별로 확인한다.
- 연결성은 단순 근접 상권 개수보다 **선정 점포 묶음의 추가 도달 범위**로 평가한다(5절).
- 접근성이 낮다고 A 가중치를 높이면 그 상권 점수는 더 낮아질 수 있다. 접근 취약을 개선하고 싶다면 별도의 연결사업 후보로 분류해야 한다.

진단 분류는 N·A의 비교집단 중앙값을 임시 기준으로 한다. 동률은 경계로 표시한다.

| 진단 | 권장 개입 |
|---|---|
| N 높음·A 높음 | 스탬프 연계 우선 검토 |
| N 높음·A 낮음 | 접근 동선·안내·횡단 개선을 먼저 검토 |
| N 낮음·A 높음 | 집객 출발점·앵커로 활용, 보상 집중은 제한 |
| N 낮음·A 낮음 | 이번 회차 확대보다 추가 조사 |

이는 정책 수단 분류이며 축제 효과가 추정됐다는 뜻은 아니다.

### V — 기초 활력

동일 기간·업종 범위의 2025년 추정매출 밀도를 전 후보 공통으로 계산한다.

```
v_sales,i = p(2025년 추정매출 / 상권면적)
V_min,i = v_sales,i
V_full,i = 0.55 v_sales,i + 0.45 p(2025년 유동량 / 상권면적)
```

- **현 단계 권장: V_min.** 16곳 전체의 일관된 유동 자료를 확보하면 V_full을 별도 비교한다.
- V_min을 쓴 후보와 V_full을 쓴 후보를 한 순위표에 섞지 않는다.
- Q에는 √V를 사용한다. 이는 증가폭 완화일 뿐, 최소 활성도를 보장하거나 높은 인기의 추가 보상을 없애지 않는다.
- “점포 20곳 미만 상권 제외”는 현장 실행 가능성과 직접 연결되지 않아 자동 게이트에서 제외한다. 필요한 것은 실제 참여 가능 점포와 수용력이다.
- 특정 업종 밀집·소규모 면적 효과가 있으므로 매출밀도·총매출·면적·업종 구성을 함께 공개한다.

### S·F — 최종 선정 필수 확인

| 게이트 | 통과 | 보류 | 제외 |
|---|---|---|---|
| 범위·참여 | 경계 적합, 상점 동의 확인 | 경계·동의 미확인 | 범위 밖 또는 참여 거부 |
| S: 보행·대기 | 접근·대기·비상 통로에 대해 담당자 검토와 운영계획 확인 | 현장 조사 전, 대체 동선 검토 중 | 위험 구간을 피할 수 없거나 통행 금지 |
| F: 운영 | 행사 시간 영업, 담당자, 스탬프 방식, 슬롯별 용량 확인 | 일부 미확인 | 휴업·운영 불가 |

안전 ‘통과’는 안전 무사고를 보증하는 인증이 아니다. 행사 책임자의 현장 검토·관계기관 협의·운영계획을 전제로 한 상태다. 법정 보도 폭이나 안전 인원 기준을 이 문서에서 임의로 정하지 않는다. 사고다발지역과 경로의 겹침은 검토 우선 경고로만 사용하며, 비해당을 안전으로 간주하지 않는다. 야간 유동량은 위험 자체가 아니라 운영 시간·인력 계획의 입력이다. [HSE 위험 평가](https://www.hse.gov.uk/event-safety/crowd-management-assess.htm)

## 4. 가중치와 결과 공개

기본안: `Q=.50N+.30A+.20√V`. 세 시나리오는 다음과 같다.

| 시나리오 | N | A | √V | 비교 목적 |
|---|---:|---:|---:|---|
| 정책 우선 — 기본 | .50 | .30 | .20 | 지원 필요성 우선 |
| 접근 우선 | .35 | .45 | .20 | 실행 동선에 더 큰 비중 |
| 활력 고려 확대 | .40 | .30 | .30 | 집객 기반의 영향 점검 |

N>A나 특정 숫자가 공모 요구에서 필연적으로 도출되는 것은 아니다. 최종 가중치는 기준의 0→1 변화가 무엇을 뜻하는지 공유한 뒤 팀·이해관계자가 결정한다. AHP를 쓰더라도 선호를 정리하는 방법이지 예측력·인과효과의 검증은 아니다. CR이 높은 응답은 이유를 확인·재검토하고, 제외 기준과 결과를 기록한다.

권역별 목적(회기 분산·이문 연결·전농 집결)은 **경로 후보와 권역 배분 제약**에 반영한다. 서로 다른 가중치 점수로 권역 간 자원을 배분하지 않는다.

출력에는 `area_id, model_version, N, A, V, Q, rank, missing_fields, access_method, scenario_rank_min/max, raw_values`를 포함한다. 정책 결정을 좌우하는 근거가 불확실하면 순위 확정 대신 조사 우선 대상으로 제시한다.

## 5. 점포 선정 — 점수 상위 K개만 뽑지 않는다

### 제약 먼저

- x_j∈{0,1}: 점포 j 선정. 보류·제외 점포는 x_j=0.
- Σx_j≤K, Σcost_j x_j≤B: 제휴 수와 예산 상한.
- L_z≤Σ(j∈z)x_j≤U_z: 팀이 승인한 권역별 범위.
- Σ(j∈상권 i)x_j≤C_i: 실제 동의·안전·운영 가능 후보 수 이내.
- 모든 권역에 전통시장을 강제로 한 곳씩 배치하지 않는다. 해당 후보가 없으면 불가능한 제약이 된다.
- 업종 다양성은 참여 대상 업종 내 구성 비율로 제한한다. 카페라는 이유만으로 자동 우대하지 않는다.
- 점포별 처리용량은 인원 유입 계획과 함께 별도 검증한다. 점포 수 상한 C_i는 방문객 수용력과 다르다.

K=60은 이전 시뮬레이션의 가정일 뿐이다. **하한 합≤K, 하한≤각 권역 후보 수, 예산·운영 동시 충족**을 먼저 검사하고 불가능하면 수를 채우기 위해 안전·동의 조건을 풀지 않는다.

### 묶음 선정의 목적

MCLP는 정해진 시설 수와 서비스 시간/거리 안에서 최대 수요를 포괄하는 모형이다. 후보 점포가 여러 수요점을 중복 포괄할 때 수요를 한 번만 세는 장점을 참고한다. 다만 기본 MCLP는 축제 경로의 순서·혼잡·점포 처리용량을 자동 해결하지 않는다. [spopt 공식 예제](https://pysal.org/spopt/notebooks/mclp.html)

팀용 확장 목적함수 제안:

```
b_j = 상권 Q_i                 # 안전·운영 확인을 통과한 점포에만 부여
d_r = 사전에 정의한 수요점 r의 수요 가중치
z_r ≤ Σ(j가 r에서 허용 도보시간 내) x_j

maximize:
  0.5 × Σ(b_j x_j)/K
+ 0.5 × Σ(d_r z_r)/Σd_r
subject to: 위 제약 및 x_j,z_r 이진
```

- 0.5/0.5도 설계 가정이며 0.25/0.75, 0.75/0.25로 비교한다. K>0, Σd_r>0을 검사한다.
- 수요점은 실제 출입구·관문·검증된 유동 지점 등이다. 자료가 없으면 동일 수요 가중치의 시연이라고 표시하고 예상 방문 인원으로 해석하지 않는다.
- 순위 점수와 포괄률을 각각 0~1 범위로 맞춰 한 단위가 목적함수를 압도하지 않게 한다.
- 같은 상권 내에서는 Q_i가 같아 개별 점포 차이를 설명하지 못한다. 그 차이는 경로의 추가 포괄 범위·운영조건·다양성 제약에서 결정한다.
- 동일 점수·동일 기여도는 사전에 정한 고정 seed 추첨 또는 ID 순으로 결정하고 규칙을 공개한다. 실제 지원 공정성을 위해 추첨 사용 여부를 팀이 결정한다.
- 선정 후 출발점–점포–종료점의 전체 보행시간·영업시간·대기공간을 검사한다. 실패하면 해당 경로 조합을 금지하고 다시 선정한다. 점포 목록만으로 순회코스가 완성됐다고 하지 않는다.
- 모든 대학 순회를 강제하지 않는다. 회기 분산형, 이문 연결형, 전농 집결형의 짧은 권역 경로를 먼저 만든다.

최적화 구현이 마감 전 어려우면 승인된 권역 범위 안에서 **미포괄 수요 추가 기여가 큰 점포를 순차 추가**하는 휴리스틱을 사용한다. 매 단계 기여를 다시 계산하고, 제약 검증·경로 점검을 유지한다. 이 경우 ‘최적해’라고 표현하지 않는다.

## 6. 당일 동적 추천

기존의 “주변이 혼잡하면 자동 가점”은 인접 점포에 한 번에 사람이 몰리는 문제를 만들 수 있다. 아래처럼 제한 절차를 먼저 둔다.

1. 통행 제한·점포 휴업·위험 신고 시 해당 점포/경로 추천 중지.
2. 입력 시각이 오래됐거나 수용력을 모르면 자동 혼잡 보정 중지. 운영자가 확인한 정적 목록만 제공.
3. 남은 처리용량과 접근 경로가 확인된 후보 사이에서 추천 배분.
4. 특정 점포에 집중되지 않도록 점포별 노출 상한과 전환 대기시간 적용.
5. 운영자가 일괄 중단·재개할 수 있도록 기록과 제어 제공.

체크인 수는 방문 사건 수이지 현재 체류 인원수가 아니다. 체류 추정에는 입·퇴장 또는 체류시간 추정과 현장 확인이 추가로 필요하다. 안전 수용 인원·체류 임계값은 현장 책임자가 정한다. [HSE 군중 모니터링](https://www.hse.gov.uk/event-safety/crowd-management-monitoring.htm)

추천 점수의 실험용 예시는 `R_jt = Q_i × a_user,j × availability_jt`이다. availability는 위험 판정이 아니라 운영자가 승인한 잔여 처리 여유의 0~1 계수다. 갱신 주기·오래된 데이터 기준·노출 한도는 리허설에서 정하며, 실시간 API의 지역 지원·갱신 빈도는 별도 확인한다.

실제 위험 대응을 A/B로 켜고 끄지 않는다. 안전 조건은 모든 구역에 동일 적용한다.

## 7. 검증과 인수 기준

| 검증 | 방법 | 통과 기준/산출 |
|---|---|---|
| 입력 | ID, 기간, 업종, 결측·대체 표시 | 중복 없음, 비교 정의 일치, 누락 열 공개 |
| 정규화 | 동률·상수·n<2·역방향 테스트 | 상수 .5, n<2 NA, 값이 좋아질 때 자기 점수 악화 없음 |
| 안전 게이트 | 높은 Q의 위험/미확인 후보 투입 | 점수와 무관하게 최종 선정 0 |
| 경로 | 철도 양쪽 출구·세 대학 기준 비교 | 실제 통로 확인, 출발점 임의 면제 없음 |
| 민감도 | 가중치 3안, N·V 정의, h 5/10/15분, 변수 하나씩 제외 | 상권별 순위 범위와 선정 빈도 공개 |
| 결측 | 경계값 스트레스·공통 축소모형 비교 | 단일 순위를 확정값으로 표현하지 않음 |
| 배분 | K 부족, 후보 부족, 예산 부족, 동률 | 불가능 상태를 명시, 안전 조건 자동 완화 없음 |
| 운영 | 데이터 지연·점포 휴업·경로 차단 | 자동 보정 중지, 승인된 대안/운영자 연결 |
| 설명 | 선정·미선정 사유 카드 | 가점 근거와 제약 사유를 분리 |

추천 결과 사유 카드:

```
점포 ID / 상권 / 권역 / 모델 버전
N·A·V와 관측 원자료
게이트 상태와 확인일
선정 사유: 지원 필요 / 추가 도달 범위 / 권역·업종 구성
보류·제외 사유: 동의 미확인 / 안전 검토 / 예산·쿼터 등
민감도: 시나리오별 순위·선정 여부
```

### 사후 성과

- 추천→방문율: 추천을 본 익명 세션 중 해당 점포 방문 세션 비율.
- 쿠폰 사용률: 발급한 쿠폰 중 실제 사용된 쿠폰 비율. 발급·노출·사용의 분모를 구별한다.
- 분산: 상위 점포 방문 집중도, 권역별 방문 비중, 미방문 후보의 신규 방문.
- 경제 효과: 동의한 점포의 같은 요일·시간대 비교 및 가능한 대조군 자료. 분기 추정매출만으로 하루 축제 효과를 분리하지 않는다.
- 실험: 안전 조건이 같은 승인 후보 내에서 추천 방식을 비교. 구역 간 이동에 따른 간섭, 날씨·공연·시간대 차이를 기록한다.
- SHAP은 향후 예측모형의 설명 수단이다. 현재 가중합은 항별 기여분으로 직접 설명한다. SHAP으로 정책 가중치의 정답이나 인과효과를 알아냈다고 주장하지 않는다. [SHAP 공식 주의사항](https://shap.readthedocs.io/en/latest/example_notebooks/overviews/Be%20careful%20when%20interpreting%20predictive%20models%20in%20search%20of%20causal%20insights.html)
